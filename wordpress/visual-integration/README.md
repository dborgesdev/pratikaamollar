# Unificação React / WordPress — instalação preparada, NÃO executada

Este pacote é uma minuta para configuração em staging depois de aprovação. Não é plugin, tema completo nem exportação importável do WoodMart. Não copie nada para a loja antes de conferir versão e capacidades do painel. Nenhum arquivo original de tema, gateway ou WooCommerce deve ser substituído.

## Caminho preferido: recursos nativos

1. Fazer backup do banco, arquivos, templates Elementor e exportar Theme Settings e header atual do WoodMart. Registrar tema/child theme, versões, IDs das páginas e configurações atuais. Criar staging isolado com pagamentos sandbox e e-mails de teste. Não atualizar plugins nesta atividade.
2. WoodMart → Header builder: duplicar o header atual como `Pratika React operacional`. Configurar logo oficial local, proporção 194×83; linha desktop 112px; navegação central; conta e link simples para carrinho React à direita. Não habilitar contador, minicarrinho, busca, comparação, wishlist ou categorias expansíveis antigas. Mobile: logo 157×67, conta/carrinho como ícones e menu acessível abaixo. O header React é relativo, não sticky: desativar sticky e barra extra neste header. Importar fontes locais Manrope e DM Serif Display, com licenças anexas.
3. Aparência → Menus: criar menu com URLs absolutas da prévia React: `/produtos`, `/categoria/acessorios`, `/categoria/maquinas-de-afiacao`, `/categoria/rebolos`, `/contato`. Ordem e slugs conferidos na prévia em 04/11/2026, rever com catálogo no dia da instalação. Conta: `https://loja.pratikaamollar.com.br/my-account/`. Carrinho: `https://pratikaamollar.smartlocal.workers.dev/carrinho`. Não usar cookies WordPress para estimar contador React. Não executar a ponte por clique de navegação.
4. Editar checkout, Minha conta e Rastrear encomenda → Page Settings (metabox WoodMart ou Elementor → Page Settings → Settings) → Custom header: selecionar apenas o novo header. Desativar título antigo somente se houver um H1 equivalente no conteúdo. Remover sidebar. Manter layout padrão/full width, nunca Elementor Canvas, que pode suprimir estrutura e hooks necessários. Manter `[woocommerce_checkout]` onde está e o shortcode nativo de conta/rastreio intacto.
5. HTML Blocks → novo bloco Elementor `Pratika footer operacional`: reconstruir `footer.html` com widgets nativos ou HTML. Upload de assets na biblioteca/child theme: substituir `PA_ASSET_BASE` pela URL local real. Não fazer hotlink da logo/fontes ao React. Footer com quatro colunas desktop, duas intermediárias e uma mobile, crédito exato e link seguro.
6. Theme Settings → presets: verificar se a versão instalada permite condições por página e substituição do conteúdo do footer. Criar preset apenas para IDs de checkout, conta, rastreamento e carrinho de fallback. Desativar prefooter, copyrights antigos, mobile bottom navbar, busca e minicarrinho herdados SOMENTE nessas condições. A documentação atual não comprova que essa versão oferece todos os campos do preset: verificar antes de salvar. A atribuição deve abranger os endpoints de conta, order-pay e order-received que usam a página base.
7. Se o preset não conseguir restringir o footer, NÃO alterar o footer global para contornar. Alternativa sem código: desativar footer/prefooter/copyrights na configuração individual dessas páginas e inserir o bloco reutilizável no fim do conteúdo Elementor, após o shortcode. Confirmar que cada endpoint realmente renderiza o conteúdo; se não renderizar, interromper essa opção e preparar integração específica no tema filho após inspeção dos hooks reais. Nunca anexar footer via CSS ou duplicar o shortcode.
8. Incluir `id="pa-content"` no contêiner de conteúdo (Advanced → CSS ID no Elementor), testar skip link e garantir H1 único. Se o Header Builder nativo não alcançar proporções/menus, usar `header.html` como HTML Block em uma única linha do header alternativo e remover os demais elementos dessa linha. O menu usa details/summary, sem JS adicional. É base visual para ajuste em staging, não equivalência homologada.

## Acabamento isolado, apenas se necessário

`assets/operational.css` contém estilos `.pa-shell` e `.pa-operational .woocommerce`, fontes locais, botões e campos. Não reorganiza DOM, não oculta mensagens, não toca iframes Mercado Pago, radios, IDs, máscaras, AJAX ou hooks de checkout. O tema ativo pode exigir seletores mais específicos após inspeção; não usar overrides indiscriminados com `!important`.

Se já existir tema filho: copiar a pasta `assets` para `pratika-visual/assets` dentro dele. Integrar (não substituir functions.php) o snippet `child-theme-loader.php`. Preencher `$page_ids` com IDs verificados, incluindo carrinho nativo de fallback se aprovado. Vem desativado com lista vazia. O PHP só acrescenta classe e carrega CSS nas páginas escolhidas. Não ativa tema, injeta header/footer nem altera opções. Caso não exista tema filho, não ativar um às cegas: registrar migração e comparação dos menus/widgets/settings antes. Pode-se usar CSS nativo condicionado se ele oferecer isolamento equivalente, mantendo URLs das fontes locais corretas.

## Páginas legais e checkout clássico

Não apontar configurações nativas a uma URL externa como se fosse um ID WordPress. Após revisão e publicação das políticas React, criar páginas WordPress locais de apoio:

- Privacidade: página curta com link absoluto visível para política React aprovada. Configurações → Privacidade → selecionar essa página. WooCommerce → Configurações → Contas e privacidade → revisar avisos de cadastro e checkout usando `[privacy_policy]`. Não ativar consentimento publicitário como condição de compra.
- Termos: página local contendo a versão integral APROVADA e versionada dos termos, mais link à referência React. WooCommerce → Configurações → Avançado → Configuração de páginas → Termos e condições: selecionar seu ID. O checkout clássico pode expandir o conteúdo dessa página junto ao checkbox; não usar apenas um redirect ou página vazia. Manter a aceitação nativa obrigatória e testar teclado, expansão e erros. Não substituir o checkbox por um link solto.
- Privacidade e termos podem aparecer também em Aparência → Personalizar → WooCommerce → Checkout, conforme tema/versão. Não alterar campos obrigatórios nessa tela nesta etapa.
- Não vincular minutas ao checkout real. Manter versão/data iguais nas cópias, checklist de atualização e revisão de cache do conteúdo público; páginas de checkout/conta e respostas personalizadas devem continuar fora de cache.
- Sem filtros PHP de URLs legais nesta entrega: evita efeitos globais e preserva o comportamento nativo.

## Rollback

Remover IDs do loader para desativar CSS; restaurar atribuições individuais de header/footer e presets; retirar blocos novos do conteúdo; restaurar exports/templates se necessário. Conferir uma única cópia de cada componente, conta, carrinho e checkout. Não desinstalar ponte/cache, trocar secrets ou limpar dados de sessão. Publicação das políticas e alterações remotas exigem autorização separada.
